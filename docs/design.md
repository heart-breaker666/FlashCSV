# FlashCSV 设计与验收

设计已审阅通过；本版精简表述并调整项目位置，功能规则保持一致。
项目根目录：`/data/fangdashuai/mycode/flash_csv`，所有开发与构建在本目录完成。

## 1. 目标与范围

用于 C++ 学习与简历展示。Linux、C++17、CMake，核心使用标准库及必要的 Linux 文件操作；核心头文件与源文件按 cloc 统计合计 1,000–2,500 行，测试和脚本另计。

支持 CSV 读写、过滤、列选择、单列分组或整体统计、COUNT/SUM/MIN/MAX/AVG、基础多线程和性能对比。输入可大于内存，聚合结果须适合分组容量；不提供 SQL、JOIN、多列分组、字段内换行、磁盘溢写或多线程导出。

## 2. 命令行

```bash
./build/flash_csv export tests/fixtures/sales.csv --output reports/filtered.csv --select city --select amount --where amount num gt 100
./build/flash_csv aggregate tests/fixtures/sales.csv --output reports/stats.csv --group-by city --agg count --agg sum amount --agg avg amount --threads 4
```

输出目录须已存在，目标文件须不存在。

| 参数 | 规则 |
|---|---|
| 输入、--output PATH | 一个普通输入文件，输出必填，不得与输入为同一文件 |
| --select COLUMN | 可重复，仅导出；省略则输出所有列，顺序与参数一致 |
| --where COLUMN TYPE OP VALUE | 可重复，按参数顺序短路 AND；str 支持 eq/ne，num 支持 eq/ne/gt/ge/lt/le |
| --group-by COLUMN | 仅聚合，可选一个列；省略则整体统计 |
| --agg count 或 --agg FUNCTION COLUMN | 至少一个；FUNCTION 为 sum/min/max/avg，按参数顺序输出 |
| --threads N | 仅聚合，默认 1，范围 1–32，指计算线程数 |
| --max-record-bytes / --batch-bytes / --batch-rows / --queue-batches | 正整数容量参数 |
| --max-groups N | 仅聚合，局部表与合并表均检查 |
| --help | 显示用法与默认值，退出 0 |

未知参数、缺值、模式冲突、重复单值参数、重复选择或聚合项、未知列、输出列名冲突报错。整数须完整解析并检查溢出；batch-bytes 不得小于 max-record-bytes。

## 3. CSV 与数值规则

- 逗号分隔，首行为表头；空或重复列名报错，数据字段数须与表头一致。
- 接受 LF、CRLF、无末尾换行；不接受单独 CR。跳过文件起始 UTF-8 BOM，不计入表头大小。
- 引号只能位于字段起始，内部逗号保留，`""` 解码为双引号；结束引号后只接受逗号、行结束或 EOF。
- 普通字段中的双引号、未闭合引号和字段内换行报错。保留空格与空字段，不转换编码或自动推断类型。
- 空白物理行解析为一个空字段；末尾单个行结束符不产生额外记录。零字节文件缺少表头而失败，仅表头文件合法。
- 构造记录时检查输入字节上限，表头同样受限；不能整文件缓存或无上限 getline 后检查。
- 输出含表头、使用 LF；需要引号的字段正确包围并转义双引号。
- 数值为 double，接受 `-?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)(?:[eE][+-]?[0-9]+)?`，须完整转换；拒绝空值、前导正号、空白、十六进制、NaN/Infinity、上下溢。
- 只在数值过滤或聚合实际需要时转换；过滤短路，已排除的行不转换后续条件或聚合字段。CSV 格式检查始终先于过滤。
- 数值比较使用精确运算；计数溢出、累计或合并求和产生非有限值均报错。输出 double 保留足够精度，不固定小数位。

## 4. 聚合与输出

COUNT 统计通过过滤的行数。AVG 使用合并后的 sum/count，不能平均局部 AVG。分组键为原始字符串，允许空键，按无符号字节字典序输出。

输出首列为分组列名，聚合列名为 count、sum(amount) 等，必须唯一。导出保持输入顺序。无匹配行时导出和分组聚合仅输出表头；整体统计仍输出一行：COUNT=0、SUM=0、MIN/MAX/AVG 为空。

## 5. 架构与容量

```text
导出：读取 → 过滤 → 选列 → 写出（主线程，保序）
聚合：主线程读取 → 有界队列 → W 个局部聚合器 → join → 合并 → 排序写出
```

| 模块 | 职责 |
|---|---|
| csv | 受限解析与转义写出 |
| query | 配置、一次性列名编译、过滤与数值转换 |
| aggregate | 局部状态、更新、合并和结果生成 |
| pipeline | 有界队列、关闭、取消与线程回收 |
| engine | 执行组织、文件生命周期与统计 |
| main | 参数、帮助、错误与统计报告 |

Row、Batch 与分组键拥有内容，批次移动入队；编译后的查询只读，每个线程独占局部表。头文件放 include/flash_csv/，实现放 src/，共享值类型保持小而简单。

默认：记录 64 KiB，批次字段内容 1 MiB/4,096 行，队列 4 批，局部表与合并表各最多 100,000 组，1 个计算线程。批次由字节或行数任一上限截断，至多留一条待加入记录。

队列 Q 批之外还有 W 个正在处理的批次及读取批次；局部表总容量随 W 增长，合并再检查全局分组上限。容器和字符串有额外开销，容量参数不等于精确 RSS 上限。平均扫描 O(S)，合并 O(WK)，结果排序 O(K log K)。

## 6. 错误、资源与统计

- 正常关闭停止投递并排空队列；取消丢弃待处理批次并唤醒所有等待者。等待条件同时检查状态。
- 任一线程、读取或启动失败，保存首个检测到的异常并取消；join 所有已启动线程后报告，不承诺最小错误行号。
- 数据错误报告原始行号、适用的列名和原因，字段样本截断；EOF 与 I/O 错误区分。
- 输出写入同目录独占临时文件，检查写入、flush、close，再用 create_hard_link 发布，拒绝覆盖目标；文件系统不支持时失败，不退回覆盖式 rename。
- 成功后删除临时路径；删除失败仅警告，不删除已发布结果。其他失败清理本次临时文件，清理错误不掩盖原错误；强制终止可能残留临时文件，不保证断电持久化。
- 成功统计写 stderr：读取/匹配/输出行数、计算线程数、总耗时、行/s、MiB/s。耗时包含打开输入至发布输出，吞吐字节含表头；失败不打印成功报告。
- 成功退出 0，参数或查询配置错误 2，数据、容量、I/O 等运行错误 1。

## 7. 验收依据

1. 格式与查询：引号转义、BOM/CRLF/EOF、空值、列顺序、数值语法、短路、错误定位均符合上述规则。
2. 聚合：五种函数、不同数值列、整体/分组空结果、排序正确。样例上海 100/200 得 COUNT=2、SUM=300、AVG=150；北京 80 得 COUNT=1、SUM=80。
3. 容量与失败：精确记录/批次边界、局部与合并超限、满/空队列取消、部分线程启动失败、写入/关闭/发布失败均能有限时间退出，保留已有文件。
4. 并发：1/2/4 个计算线程的计数与分组精确一致；浮点满足 `abs(a-b) <= 1e-9 * max(1, abs(a), abs(b))`，用于正常数值范围的测试，并发失败测试须有超时。
5. 性能：固定种子数据，Release 下同配置至少三次，报告中位耗时、MiB/s、峰值 RSS及 CPU/存储/缓存条件。比较输入规模、线程数、分组数；不预先承诺加速比。
6. 规模：百万/千万行及条件允许时的大于内存数据；未实测的规模明确标注。核心头文件与源文件合计符合行数范围。

初始案例在 tests/fixtures/cases.json；并发和 I/O 故障由实现阶段建立测试。实施顺序仅记录在 implementation-plan.md，实测结果在后续基准报告中记录。
