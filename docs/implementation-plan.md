# 实施顺序

行为和验收仅引用 [设计](design.md)，本文件不重复规则或预写实现代码。
各任务依次推进，状态均为未开始；当前授权仅为开发前准备。

| 任务 | 涉及模块/文件 | 完成条件 | 设计依据 |
|---|---|---|---|
| 1. CSV 读写与最小构建 | CMakeLists.txt；csv、共享值类型；CSV 测试 | 格式、转义、行号和记录/批次边界通过 | §3、§5、§7.1/3 |
| 2. 查询与过滤 | query；查询测试 | 列编译、数值转换、选择顺序和短路通过 | §2–3、§7.1 |
| 3. 导出命令 | main、engine；CLI/输出测试 | 保序导出可用，退出码、输出保护与统计正确 | §2、§4、§6 |
| 4. 分组聚合 | aggregate、engine；聚合测试 | 五种函数、空结果、排序及直接合并超限通过 | §4–5、§7.2/3 |
| 5. 有界队列 | pipeline；队列测试 | 正常关闭排空，满/空等待均可取消 | §5–6、§7.3 |
| 6. 并行聚合 | pipeline、engine；并发测试 | 1/2/4 工作线程结果一致，所有失败路径回收线程 | §5–6、§7.3/4 |
| 7. 完整验收 | tests/；README | 28 个初始案例及容量/I/O 故障在 Debug/Release 通过 | §7.1–4 |
| 8. 基准与展示 | tools/；基准报告 | 结果校验、实际性能/RSS、核心行数有证据 | §7.5–6 |

执行每项时：建立能验证行为的测试 → 最小实现 → 运行相关检查 → 更新交接。Task 4 可先串行验证聚合逻辑，Task 6 接入最终流水线。

开发和构建仅使用项目本目录；命令见 README。无需为每项另建计划或再次复制设计。
