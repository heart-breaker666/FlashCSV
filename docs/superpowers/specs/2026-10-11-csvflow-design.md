# CsvFlow 设计说明

日期：2026-10-11

阶段：讨论方案已确认，本文待用户审阅。本文定义设计，不代表实现或测试已完成。

## 1. 项目目标与约束

CsvFlow 是一个用 C++ 编写的命令行 CSV 数据处理引擎，用于学习 C++、模块设计和并发编程，同时形成可通过正确性测试与性能数据展示的简历项目。

用户确认的要求：

- 核心 C++ 代码约 1,000–2,500 行，测试、文档和数据生成脚本另计。
- 采用均衡型功能范围：流式读取、过滤、列选择、分组聚合、基础多线程、性能对比。
- 导出模式单线程并保持输入顺序；聚合模式采用多线程局部聚合，再合并结果。
- 队列和分组数量设置容量上限，超限时明确报错。
- 需要数值处理的字段为空或非法时立即报错。

采用 Linux、C++17、CMake，核心实现使用标准库。项目根目录为 `/data/fangdashuai/mycode/csvflow`。

“大规模”指输入文件可以大于可用内存。程序不缓存整个文件；聚合结果必须适合配置的分组容量。第一版不承诺处理任意数量的不同分组，也不承诺精确的进程 RSS 上限。

成功标准：结果可核对，错误可定位，失败时线程可退出；通过相同数据集展示文件大小、线程数和分组数量对耗时与内存的影响。没有预设的吞吐量或加速比承诺。

## 2. 功能范围

### 2.1 第一版包含

1. CSV 表头解析、逐批读取、正确转义写出。
2. 按列名选择输出列。
3. 显式区分字符串与数值的过滤条件，多个条件按 AND 组合。
4. 按单个字符串列分组，或者对全文件做整体统计。
5. `COUNT / SUM / MIN / MAX / AVG` 聚合。
6. 聚合工作线程数可配置；单线程与多线程复用过滤和聚合逻辑。
7. 批次与队列容量限制、分组数量限制、并发错误传播与取消。
8. 运行统计、正确性测试和可重复的性能基准。

### 2.2 留作后续扩展

- SQL 解析器、OR 或嵌套表达式、JOIN、多列分组。
- 明细数据排序、索引、查询优化器、分布式执行。
- 字段内换行、自定义分隔符、自动类型推断。
- 跳过错误记录、缺失值填充、磁盘溢写与外部聚合。
- 多线程导出、SIMD、`mmap`、零拷贝解析。

第一版对分组结果排序是为了稳定输出，并非提供通用 `ORDER BY`。

## 3. 命令行接口

### 3.1 过滤与导出

```bash
csvflow export sales.csv \
  --output filtered.csv \
  --select city --select amount \
  --where amount num gt 100
```

输出顺序与输入顺序一致，输出列顺序与 `--select` 出现顺序一致。省略 `--select` 时输出全部输入列，输出始终包含表头。

字符串过滤示例：

```bash
csvflow export sales.csv \
  --output shanghai.csv \
  --where city str eq 上海 \
  --where amount num ge 100
```

### 3.2 分组聚合

```bash
csvflow aggregate sales.csv \
  --output stats.csv \
  --group-by city \
  --agg count \
  --agg sum amount \
  --agg avg amount \
  --threads 4 \
  --max-groups 100000
```

结果示例：

```csv
city,count,sum(amount),avg(amount)
上海,2,300,150
北京,1,80,80
```

### 3.3 整体统计

```bash
csvflow aggregate sales.csv \
  --output totals.csv \
  --agg count \
  --agg sum amount \
  --threads 1
```

不指定 `--group-by` 时，对所有通过过滤的记录计算一个整体结果。

### 3.4 参数规则

| 参数 | 语义 |
|---|---|
| `export / aggregate` | 必须选择一个执行模式 |
| 输入文件 | 仅接收一个普通文件路径 |
| `--output PATH` | 必填，输出到一个新文件，默认不覆盖已有路径 |
| `--select COLUMN` | 可重复，仅适用于导出；不允许重复选择同一列 |
| `--where COLUMN TYPE OP VALUE` | 可重复，两种模式均可使用；条件按参数顺序求值并短路 |
| `--group-by COLUMN` | 可选，只能指定一次，仅适用于聚合 |
| `--agg count` | 行数统计，不需要数值列 |
| `--agg sum/min/max/avg COLUMN` | 可重复，至少一个聚合；重复的函数与列组合报错 |
| `--threads N` | 仅适用于聚合，默认 1；接受 1–32 的整数，表示计算线程数 |
| `--max-groups N` | 仅适用于聚合，正整数；每个局部表与最终合并表均检查此上限 |
| `--max-record-bytes N` | 单条输入记录的字节上限，不包含行结束符 |
| `--batch-bytes N` | 一个批次内字段内容字节数的累计上限 |
| `--batch-rows N` | 一个批次内记录数上限 |
| `--queue-batches N` | 聚合输入队列的批次数上限 |
| `--help` | 显示用法和默认值 |

`TYPE=str` 支持 `eq/ne`，按字段内容的字节精确比较。`TYPE=num` 支持 `eq/ne/gt/ge/lt/le`。数值比较不使用模糊相等；测试浮点聚合结果的容差属于验证规则。

未知参数、模式不匹配的参数、缺少参数值、非法上限、未知列名，在正式处理数据前报错。正整数参数须完整解析并检查溢出。批次字节上限不得小于单条记录字节上限。

列名或字符串值包含空格时由调用者通过 shell 引号传递，不引入额外的表达式解析语言。

输出路径不得与输入文件指向同一个文件。参数与表头解析完成后，提前检查输出路径与目录；最终发布时仍须检查目标是否已存在，并采用不覆盖目标的发布方式。

## 4. CSV 与类型规则

### 4.1 CSV 格式

- 使用逗号分隔，第一条记录为表头；没有任何内容的文件报“缺少表头”。
- 接受 LF、CRLF，以及末条记录没有行结束符的文件。单独的 CR 不作为合法行结束符。
- 跳过文件起始的 UTF-8 BOM，BOM 不计入表头记录大小。字段按字节保存，不做字符编码转换或 Unicode 规范化；建议输入 UTF-8。
- 引号必须从字段起始处开始。带引号字段内可以出现逗号，`""` 表示一个双引号。
- 结束引号后只接受逗号、合法行结束符或文件结束。未加引号的字段内出现双引号报错。
- 不支持字段内换行；检测到时报告记录起始行号和原因。
- 保留字段中的空格，不自动裁剪。
- 允许空字段，包括空分组键。空列名、重复列名报错。
- 每条数据记录的字段数量必须与表头一致。空白物理行按一个空字段的记录解析，不静默跳过。
- 文件末尾的一个行结束符不额外产生记录；连续行结束符之间的空记录按上一条规则处理。
- 输出包含表头，统一使用 LF。含逗号、双引号或换行的字段使用引号包围，并转义内部双引号。

读取器在构造记录期间检查字节上限，不能先无上限地 `getline` 再检查大小。表头也受单条记录上限约束。

### 4.2 数值

数值使用 `double`。接受可选负号、十进制整数或小数、可选指数，例如 `12`、`-1.5`、`.5`、`1.`、`2e3`。语法为 `-?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)(?:[eE][+-]?[0-9]+)?`；此表达式定义接受范围，不要求实现使用正则库。要求完整消费字段，不接受前导正号、首尾空白、十六进制、NaN、Infinity、溢出或下溢。

解析失败时报告原始行号、列名和原因；错误信息中的字段样本截断到有限长度。命令行数值比较值按相同规则预先解析。

需要数值处理时才转换字段：

- 已被前面的过滤条件排除的行，不继续执行后面的条件。
- 未通过过滤的行，不解析其聚合字段。
- 未参与数值过滤或聚合的普通字段，可以为空或包含任意字符串。
- CSV 格式及字段数量检查发生在过滤前，对所有读取到的记录执行。

`count` 统计通过过滤的行数。数值聚合不存在忽略 NULL 的规则；通过过滤且需要聚合的数值字段必须合法。若累计 SUM、AVG 的内部求和或合并结果变为非有限值，则报错。计数溢出也报错。

输出数值使用足以保留 `double` 精度的表示，不强制固定小数位；空结果的 MIN、MAX、AVG 输出空字段。

### 4.3 聚合输出与空数据

- 有分组时，第一列保留输入分组列名，后续按 `--agg` 顺序命名为 `count`、`sum(amount)` 等。
- 输出列名必须唯一；若生成列名与分组列名冲突，执行前报错。
- 分组键按无符号字节字典序排序，不采用语言环境的拼音或本地排序规则。
- 没有数据行或过滤后没有记录：导出仅写表头；分组聚合仅写表头。
- 无分组的整体统计仍写一条结果：COUNT 为 0，SUM 为 0，MIN/MAX/AVG 为空字段。
- AVG 为该列 SUM / 合法参与行数，计数使用整数，不合并各线程平均值的简单平均。

## 5. 架构与数据流

```text
CLI → QuerySpec → 读取并验证表头 → CompiledQuery
                                      │
                   ┌──────────────────┴──────────────────┐
                   │                                     │
              export 模式                          aggregate 模式
                   │                                     │
              CsvReader                             CsvReader
                   │                                     │
              过滤与列选择                         BoundedQueue<Batch>
                   │                                     │
              CsvWriter                           N 个聚合工作线程
                   │                                     │
             发布输出文件                       各自持有局部分组表
                                                         │
                                               join → 主线程合并
                                                         │
                                               分组键排序 → 写出
                                                         │
                                                    发布输出文件
```

导出由主线程完成。聚合时主线程读取和投递批次，N 个工作线程消费；正常结束后主线程等待工作线程完成，再合并局部状态并写出。不存在输出队列，也不存在工作线程之间共享并更新的聚合表。

`--threads 1` 仍使用相同聚合流水线，意味着一个读取线程和一个计算线程。基准中的“单线程模式”指一个计算线程，并非整个进程只有一个线程；README 和测试报告须明确这一点。

## 6. 模块职责与数据所有权

| 模块 | 职责 | 依赖 |
|---|---|---|
| `csv` | 受限读取、表头和记录解析、CSV 转义写出 | 标准库 |
| `query` | CLI 配置模型、列名解析、条件编译、过滤、数值转换 | 标准库、记录类型 |
| `aggregate` | 分组状态、更新、合并、结果生成 | 已编译聚合配置、数值转换 |
| `pipeline` | 有界队列、关闭与取消、异常记录、工作线程回收 | 标准库、批次类型 |
| `engine` | 组织两种模式、容量检查、输出生命周期、统计 | 上述模块 |
| `main` | 参数解析、帮助信息、调用引擎、错误和统计打印 | 查询配置、引擎 |

概念接口：

```text
QuerySpec                         保存用户给出的列名、类型和操作
compile(header, spec)             → CompiledQuery：列下标和已解析常量
CsvReader::next_batch()           → 拥有记录内容的 Batch，或 EOF
Filter::matches(row)              → 是否保留
Aggregator::consume(row)          → 更新本线程状态
Aggregator::merge(other)          → 合并计数、和、最小值、最大值
CsvWriter::write(row)             → 转义并写出
Engine::run(spec)                 → RunStats，失败时抛出异常
```

具体约束：

- `Row` 拥有字段字符串和原始行号；`Batch` 拥有记录集合。
- 队列传递批次使用移动语义。工作线程不得保存指向下一次会被复用的读取缓冲区的引用。
- `CompiledQuery` 在启动线程前完成，执行期间只读。
- 分组表拥有分组键字符串。批次释放后，分组键仍有效。
- 每个局部状态包含整数计数以及所需的 sum/min/max；AVG 使用 sum 与 count 合并。
- 结果排序保存对稳定分组表的引用或迭代器；排序期间不再插入、删除分组，避免额外复制所有键。
- 普通行处理以值和移动语义为主，不为每行使用 `shared_ptr`。仅线程取消状态是共享控制信息。

## 7. 容量与复杂度

默认参数：

| 项目 | 默认值 |
|---|---:|
| `max-record-bytes` | 65,536 字节，64 KiB |
| `batch-bytes` | 1,048,576 字节，1 MiB |
| `batch-rows` | 4,096 |
| `queue-batches` | 4 |
| `max-groups` | 100,000 |
| `threads` | 1 个计算线程 |

任一批次达到记录数或字段内容字节数上限后封装投递。若下一条记录会超过批次上限，将其留作下一批的第一条；最多持有一条这样的待加入记录。不得通过无限读取积累待加入记录。

设 Q 为队列容量、W 为计算线程数、G 为分组上限。除队列中的 Q 个批次外，最多还有 W 个工作线程正在处理的批次、一个读取中的批次与一条待加入记录。

每个局部表最多 G 个分组，合并表最多 G 个分组。合并时逐个处理局部表并及时释放已合并状态；峰值仍须考虑多个局部表与结果表同时存在。局部表都未超限，不代表全局不同分组数量不超限，合并时必须再次检查。

内存随批次容量、字段数量、线程数、分组数量和分组键长度增长；不随总输入行数线性增长。字符串对象、vector 容量、哈希桶、排序引用与分配器都有额外开销，所以这里提供容量约束，不声称 `batch-bytes` 是精确的进程内存限制。

设输入总字节数为 S，实际分组数为 K。在固定条件数和聚合项数时：

- CSV 解析与导出约 O(S)。
- 聚合使用哈希表，平均情况下扫描与更新约 O(S)。
- 局部状态合并约 O(WK)，输出排序约 O(K log K)。
- 读取和解析是一个串行阶段，可能限制多线程的最大加速效果。

## 8. 错误传播与输出生命周期

### 8.1 队列状态

队列区分三种状态：

1. **开放**：生产者和消费者根据容量等待与读写。
2. **正常关闭**：EOF 后不再接收新批次；消费者排空已有批次后退出。
3. **取消**：发生异常后停止处理，丢弃未处理批次并唤醒所有等待者。

等待条件必须同时检查队列状态，不能只检查“非空”或“未满”。

### 8.2 失败流程

主线程或任意工作线程遇到失败时，保存首个检测到的异常、取消队列并唤醒所有线程。已启动的线程无论正常或失败都必须 join；禁止工作线程异常逃逸导致 `std::terminate`。

首个检测到的错误不一定是文件中行号最小的错误，不为追求最小行号而继续扫描。合并、排序或写出阶段的异常同样终止本次执行。

错误覆盖：参数、CSV 格式、未知列、数值转换、记录超限、分组超限、文件读写和线程启动失败。读到 EOF 与底层 I/O 错误必须区分。

### 8.3 输出文件

- 在目标目录创建本次任务专属的临时文件，避免覆盖他人的临时文件。
- 数据写完后检查 flush 和 close 的结果，成功后发布到目标路径。
- 发布必须拒绝覆盖已有目标。仅先做一次 exists 检查再使用可覆盖的 rename 不足以满足此规则。
- Linux 下选择同目录临时文件与 `std::filesystem::create_hard_link(temp, target)` 发布：目标已存在时操作失败；成功时目标原子地指向已完整写出的文件，再删除临时路径。目标目录所在文件系统须支持硬链接，否则明确报错，不退回可覆盖的 rename。这部分封装在输出生命周期代码中，不影响 CSV 编码器。
- 发布成功后，若删除临时路径失败，最终结果仍视为成功，向标准错误报告残留临时路径；不得因此删除已发布结果。其他失败路径中的清理错误不能掩盖原始错误。
- 失败时清理本次临时文件，保持已有文件完整；不递归清理目录。
- 第一版不提供覆盖已有输出的开关，不承诺断电情况下的持久化保证；进程被强制终止时可能留下临时文件。

### 8.4 运行统计

正常结束后向标准错误输出：

- 读取的数据行数，不含表头。
- 通过过滤的行数。
- 输出行数，聚合时即结果记录数。
- 实际计算线程数。
- 总耗时、行/秒、输入 MiB/秒。

吞吐量使用完整输入文件字节数和从打开输入到发布输出完成的总耗时计算，包含表头和写出耗时。失败时明确报告失败，不输出易被误认为成功的吞吐量报告。

退出码：成功为 0，参数错误为 2，运行期间的数据、容量或 I/O 错误为 1。`--help` 正常退出为 0。

## 9. 测试与验收

### 9.1 手工可核对数据

```csv
city,amount
上海,100
北京,80
上海,200
```

无过滤时：上海 COUNT=2、SUM=300、MIN=100、MAX=200、AVG=150；北京 COUNT=1、SUM=80、MIN=80、MAX=80、AVG=80。

使用 `amount num gt 100` 后仅保留上海的 200。整体统计无过滤时 COUNT=3、SUM=380、AVG=380/3。

### 9.2 正确性测试

- CSV：逗号、双引号转义、空字段、CRLF、BOM、没有末尾换行、边界大小记录。
- 非法 CSV：不闭合引号、字段内换行、结束引号后多余内容、字段数量错误、空与重复表头。
- 查询：列顺序、未知列、重复选择、多个 AND 条件、字符串 `001` 与数字比较的区别。
- 数值：合法指数、负数、非法及空字段、非有限值、数值范围错误、累计溢出。
- 聚合：五种函数、不同数值列、多组、空分组键、整体统计、没有匹配行。
- 输出：正确转义、稳定分组顺序、已有目标保护、写出失败后临时文件清理。

### 9.3 并发与容量测试

- 同一数据分别使用 1、2、4 个计算线程，COUNT 和分组集合完全一致。
- 一般规模测试中的浮点结果采用 `abs(a-b) <= 1e-9 * max(1, abs(a), abs(b))` 比较；用适当数值范围的数据，不将其作为任意病态浮点输入的保证。
- 分组数刚好等于上限时成功，超出上限时失败。
- 构造各局部表未超限、合并后全局分组超限的输入，验证合并检查。
- 使用极小队列，在生产者等待队列容量时触发消费者错误，验证无死锁。
- 在消费者等待输入时触发读取错误或取消，验证全部线程退出。
- 线程启动部分失败时，已启动线程也能被取消并回收。
- 并发失败测试设定超时；线程检测工具可用于检查共享控制状态的数据竞争。

### 9.4 性能与内存基准

数据生成脚本使用固定种子并记录生成参数；生成和校验不计入引擎运行耗时。提供百万行、千万行规模，并支持生成大于测试机器可用内存的文件。分组数、字段宽度、过滤通过率可配置。

至少开展三个实验：

1. 固定较小分组数、字段宽度、线程数和容量配置，增大文件，验证峰值 RSS 不随输入规模近似线性增长。
2. 固定数据和分组数，比较 1/2/4 个计算线程的耗时；同时核对结果，记录读取解析瓶颈。
3. 增大分组数，观察 RSS 增长并验证超限报错；区分局部表上限与合并表上限。

每次记录 CPU、内存、编译器、构建选项、存储类型、输入字节数、行数、字段数、分组数、线程数、容量参数、耗时、MiB/s 和峰值 RSS。使用外部工具如 `/usr/bin/time -v` 采集峰值 RSS，不要求核心程序内部提供跨平台测量。

发布构建下每个配置运行至少 3 次，报告中位耗时。记录首次和后续运行条件，承认文件系统缓存对结果的影响，不将缓存条件不同的测量直接解释为线程加速。

最终验收：核心代码在目标范围内；正确性、容量和并发失败测试通过；生成可复现的基准报告。数据大于可用内存的实验若因机器存储条件无法执行，应明确列出已验证的数据规模，不声称已经完成该规模的实测。
